# Streamlining Multimodal Dataset Preparation with Mixpeek and Tigris

## Introduction: The Challenge of Data Preparation

Preparing large-scale **datasets for AI training** is often a complex, multi-step ordeal. Traditionally, teams stitch together manual and fragmented tools – for example, storing raw files in S3, running ad-hoc scripts or SageMaker jobs for feature extraction, then managing separate indexing and annotation processes. This DIY approach is time-consuming and error-prone. As data volume and modality (text, images, audio, video) grow, the difficulty compounds. Legacy pipelines demand significant custom code and coordination across storage, compute, and database layers. In short, turning raw multimodal data into a high-quality, labeled training dataset can become a bottleneck in ML projects.

**Enter Mixpeek and Tigris.** These two technologies combine to offer an end-to-end solution for dataset engineering that bypasses the usual headaches. **Mixpeek** serves as a *semantic layer* on top of unstructured data, automatically extracting rich features (embeddings, transcripts, detections, etc.) and making content searchable and analyzable. **Tigris** provides the *storage backbone*, a globally distributed, S3-compatible object store that ensures data is accessible with low latency worldwide. Together, Mixpeek + Tigris form a modern pipeline: as data is ingested into storage, Mixpeek indexes and organizes it semantically, ready for retrieval, clustering, and model training. This deep-dive will explore how this integration works and how it **streamlines multimodal dataset preparation** for real-world use cases.

## Mixpeek: A Semantic Layer for All Your Data

Mixpeek is a **multimodal data processing and retrieval platform** designed to make sense of unstructured content. In essence, Mixpeek converts raw files – whether documents, images, videos, or audio – into **structured, searchable representations**. It does this by automatically **extracting features** from the files using AI models and storing those features in optimized indexes. For example, Mixpeek can transcribe audio, detect objects in images, segment video into scenes, compute embeddings for text, and more. These become rich metadata that you can query semantically (e.g. find images with “mountains and a lake” or videos “mentioning climate change”). The platform was built from the ground up to handle *multimodal content*, allowing developers to search and analyze different content types in a unified way.

**How it works under the hood:** Mixpeek functions like a “Multimodal Data Warehouse.” When you feed in raw data, it organizes it into a hierarchy of **buckets, objects, collections, and features** (analogous to databases, tables, and columns in a warehouse). It comes with many *pre-built feature extractors* for text, images, audio, and video, and you can chain these in **custom pipelines** to suit your needs. Crucially, Mixpeek is extensible – you can plug in **custom models or algorithms** (PyTorch, TensorFlow, ONNX, etc.) as custom extractors to handle domain-specific feature extraction. This means whether you need to run an OCR, an object detector, a sentiment analyzer, or a proprietary ML model, you can integrate it into Mixpeek’s pipeline. All extracted features are stored in specialized feature stores (including vector databases for embeddings), so that they can be efficiently queried later. Mixpeek continuously manages and updates these extractors and indexes behind the scenes, so you always leverage state-of-the-art models without rebuilding your pipeline from scratch.

**Core capabilities of Mixpeek include:** semantic search, similarity-based retrieval, and automated data structuring. It provides a higher-level interface where you can issue natural language queries or example-based queries to find relevant data points across millions of files. It also supports applying **Taxonomies** (joining data across modalities by feature similarity) and **Clustering** (grouping similar items) to impose structure on your content. For instance, Mixpeek can automatically group unlabeled images into clusters based on visual similarity, or join images with text descriptions based on semantic matches. This is extremely powerful for dataset curation: you can discover inherent categories and relationships in unstructured data without manual labeling upfront. Mixpeek essentially *transforms raw multimodal data into a structured, high-quality dataset* ready for analysis and model training. As the Mixpeek team puts it, it offers *“a seamless path from raw data to analysis-ready datasets with built-in semantic understanding and versioning.”*

## Tigris: Globally Distributed Object Storage as the Foundation

Tigris is the **object storage layer** that perfectly complements Mixpeek’s capabilities. Tigris provides a *globally distributed, S3-compatible object storage service*. In practice, it behaves like a superset of Amazon S3: you can use the same S3 API and tools, but your data is not bound to a single region. Instead, Tigris **automatically distributes data across multiple regions**, placing content close to users for low-latency access worldwide. This global design means you *don’t need a separate CDN* to cache content in different geographies – any object stored in Tigris is available “everywhere” with local-like speeds by default. For AI dataset work, this is a boon: whether your training jobs or annotation teams are in New York or London or Tokyo, they can access the same data quickly.

Equally important, **Tigris has no egress fees**. Traditional cloud storage often charges expensive bandwidth fees when you pull data out (for example, an ML pipeline reading thousands of images from S3 can incur significant egress costs). Tigris eliminates that concern – you can move data out freely, which encourages heavy data processing workflows (like feature extraction or big training jobs) without worrying about racking up transfer fees. In addition, Tigris provides strong consistency guarantees (thanks to a foundation built on FoundationDB) and built-in support for object versioning and notifications. Strong consistency ensures that if your pipeline is reading and writing to the storage (perhaps updating labels or augmented data), you won’t encounter stale reads or eventual consistency issues. And with **object change notifications**, Tigris can actively alert when new data arrives in a bucket – a perfect trigger for Mixpeek to start processing newly added files in real-time.

In summary, Tigris acts as a **high-performance, globally accessible data lake** for your unstructured data. You still use familiar S3 client code or commands to interact with it, but you gain global low-latency distribution and an easier cost model. Developers can even migrate existing S3 buckets to Tigris using “shadow buckets” with zero downtime or cost, then plug that storage into Mixpeek. With Tigris as the storage foundation and Mixpeek as the semantic layer, we get a powerful synergy: *storage that scales and serves data everywhere, and a layer that makes that data intelligently searchable and organized.*

## Seamless Integration: How Mixpeek + Tigris Work Together

When combining Mixpeek and Tigris, the workflow of dataset preparation becomes remarkably streamlined. Here’s an overview of the **pipeline** that these two tools provide, from raw data to a refined training dataset:

Raw content in an object store (e.g., Tigris) flows through a series of feature extraction tasks (center) using various AI models, and the extracted features are indexed in a vector store. This semantic layer enables search, clustering, and analysis on top of the raw data.*

1. **Data Ingestion from Tigris:** All your raw data (images, videos, audio files, PDFs, text documents, etc.) is stored in Tigris buckets. Because Tigris is S3-compatible, connecting it to Mixpeek is straightforward – in the Mixpeek dashboard you simply add a new data source of type "Tigris", providing the bucket name, Tigris endpoint URL, and your access keys. Mixpeek will then have secure read access to the bucket. Thanks to Tigris’s notification capability, Mixpeek can discover new or updated files promptly. As soon as the connection is set up, Mixpeek **automatically begins scanning the bucket and ingesting files**. There’s no need to manually export or list objects; Mixpeek treats Tigris as just another supported storage backend (just like AWS S3, GCS, etc., but with the added global performance benefits).

2. **Feature Extraction Pipelines:** Once Mixpeek detects files in the Tigris bucket, it kicks off the **ETL process** under the hood. For each object (or group of files), Mixpeek applies the relevant **feature extractor pipelines** configured for your use case. This is the “Transform” step where raw content is turned into meaningful features. For example, an image might go through an image feature extractor that generates a vector embedding of its visual content and identifies any objects or tags present. A video file might be automatically segmented into scenes or keyframes, with each frame analyzed (e.g., detecting objects or transcribing speech in the audio). A PDF or text document could be processed by an NLP pipeline to pull out text embeddings, named entities, key phrases, or even a summary. Mixpeek’s library of extractors covers common needs – text, metadata, media, etc. – and you can insert custom steps as needed. You have fine-grained control over how extraction is done: pipelines can be defined to split or group documents, produce multiple outputs, or merge features from multiple models. This is where you might incorporate **multiple modeling frameworks in one flow** – for instance, using a PyTorch-based image classifier, an ONNX object detector, and a TensorFlow text encoder all in the same pipeline. Mixpeek’s flexible architecture supports these custom extractors and even integration with external tools or services. The result of the extraction stage is that each raw file from Tigris is now represented by a rich set of features (embeddings, labels, transcripts, etc.), which are stored as structured **documents** in Mixpeek.

3. **Indexing and Feature Storage:** After extraction, Mixpeek performs the “Load” step: it **indexes the extracted features** into its feature stores for fast retrieval. This means all those embeddings and metadata get loaded into optimized databases (for example, vector indexes powered by Qdrant, as Mixpeek uses under the hood). Each piece of content is now indexed by its semantic content rather than just an ID or filename. Mixpeek ensures these indexes stay up-to-date; if you add new data or re-run extraction with updated models, the indexes can be refreshed seamlessly. Because Tigris provides strong consistency, Mixpeek always reads the latest version of each object, and any updates propagate globally. At this stage, your dataset in Tigris has been fully “decoded” by Mixpeek – it's no longer just opaque files, but a **queryable semantic database** of your data. Every image, video, and document is mapped to vectors and attributes that capture its meaning and content.

4. **Semantic Search and Discovery:** With the feature store populated, you can now **retrieve and explore the data in advanced ways**. Mixpeek’s retrieval engine lets you perform vector searches, apply filters, and combine modalities in queries. For example, you can ask Mixpeek to find *“all images of machinery with a blue background”* or *“videos featuring outdoor scenes that also contain the word ‘safety’ in their transcripts.”* These kinds of queries go far beyond simple keyword search – they leverage the extracted features (visual embeddings, transcript text, etc.) to find data that matches the semantic criteria. Because Mixpeek supports *hybrid retrieval*, you can mix vector similarity with metadata filters for very precise results across modalities. This capability is incredibly useful for building training datasets: it allows developers to **cherry-pick specific slices of data** (for instance, all documents about a certain topic, or all images of a rare object) from a huge corpus, just by querying rather than manually combing through files.

5. **Clustering and Outlier Detection:** Beyond ad-hoc search, Mixpeek can also **analyze global patterns in your dataset**. Using its Clustering functionality, Mixpeek groups similar documents together based on feature similarity (this is effectively the multimodal analog of an SQL GROUP BY on content). The platform can run algorithms like k-means or DBSCAN on the embeddings to identify clusters of related items. Why is this valuable? For one, it helps reveal the **implicit structure and categories** in an unlabeled dataset. You might discover, for example, that your image dataset naturally clusters into 5 distinct scene types. Additionally, clustering makes it easier to spot **outliers or minority clusters** – those are potentially anomalies or new classes of data. Mixpeek’s philosophy is that *“out-of-distribution data isn’t noise – it’s insight.”* Instead of discarding the weird or unclassified data, Mixpeek helps you *extract it, cluster it, and understand it*. We’ll explore a concrete example of this in the next section. The key point is that by clustering your Tigris data’s features, Mixpeek can highlight patterns (and anomalies) that you might not have known existed in your collection. This is immensely helpful for curating a balanced and comprehensive training set. You can ensure your model isn’t only trained on the “obvious” in-distribution data, but also includes edge cases and corner scenarios that the clustering surfaces.

6. **Enrichment and Taxonomy Mapping:** Mixpeek also allows joining and enriching data in a process analogous to SQL JOINs, termed **Taxonomies**. You can enrich one collection of data with information from another based on feature similarity. For example, if you have a collection of images and a separate collection of textual descriptions, a taxonomy can **link each image to the closest matching text** (perhaps to auto-tag the image with a caption). In dataset preparation, this can be used to attach metadata or weak labels to content automatically. Mixpeek’s taxonomies and clustering together provide a way to impose a **human-understandable structure** on your unstructured data – grouping items and labeling relationships between them. By the time you’ve applied these, your raw data in Tigris has effectively been turned into an organized dataset: files grouped into clusters or categories, and enriched with relevant tags or metadata for each group.

7. **Dataset Assembly and Export:** The final step is assembling the curated data for training. After using search, clustering, and taxonomy operations to isolate the data you care about, Mixpeek lets you compile those into a **curated collection** – essentially the subset (or full set) of data with all the extracted features and labels that you want to use for training. Because Mixpeek keeps track of all data versions and lineage, you can version this assembled dataset for reproducibility. At this stage, you might integrate with human annotation workflows if needed (more on that shortly), or proceed directly to model training. Mixpeek doesn’t lock you in here: you can easily pipe the resulting dataset into your preferred ML framework. In fact, Mixpeek’s SDK allows you to fetch data and features directly into Python, PyTorch, TensorFlow, or Hugging Face datasets, etc., ready to be loaded into a model training pipeline. This means the transition from “curated in Mixpeek” to “feeding a training script” is seamless. For instance, you could use Mixpeek’s Python client to query all images labeled as a certain cluster, get their S3 (Tigris) URLs or the raw bytes and any pre-tags, and then load them into a PyTorch `DataLoader` for fine-tuning a vision model. Mixpeek essentially serves as the intelligent data broker, and you are free to use the data in any downstream training or fine-tuning job.

In summary, integrating Tigris and Mixpeek yields a **highly automated, intelligent data pipeline**. Raw data goes into Tigris; Mixpeek ingests and enriches it; you interact with the data semantically to curate your training set. Compared to the DIY approach (writing custom extractors, managing a vector DB, manually finding anomalies, etc.), this approach dramatically **cuts down manual effort and complexity**. Mixpeek’s automated feature extraction and pre-tagging mean much of the data labeling grunt work is handled upfront. Rare or edge-case data that could easily be overlooked is immediately surfaced for your attention. And you maintain full traceability – every transformation or annotation is versioned, so you know exactly how the final training set was derived. ## Use Case 1: Finding Anomalies and New Classes via Clustering

One of the most compelling benefits of Mixpeek’s semantic layer is how it enables **outlier detection and active learning** in your dataset. Let’s say you’ve trained a classification model on your data, but during testing you encounter a bunch of “unknown” or misclassified examples – things that fall outside your current classes. In many workflows, these *out-of-distribution (OOD)* samples might be discarded or ignored. However, they likely represent **new patterns or rare events** that your model failed to cover. Mixpeek + Tigris makes it easy to turn these anomalies into actionable insights.

For example, consider a content moderation scenario (brand safety, insurance claims, security footage analysis, etc.). You have a classifier that flags inappropriate or non-compliant content. Occasionally it encounters images or videos that don’t clearly fit any known category – *the weird stuff*. Instead of throwing these “classification rejects” away, you can feed them to Mixpeek for clustering and exploration. Mixpeek allows you to **build custom low-level feature extractors for the specific cues** you care about – maybe a detector for unusual motion patterns in videos, or a color anomaly detector for images, or an audio irregularity detector for sound clips. These features, focused on the peculiar aspects of the OOD data, are extracted for all content in your Tigris bucket. Then, using Mixpeek’s clustering, you group data points by these feature similarities to see if those odd samples actually form their own cluster or clusters.

Indeed, Mixpeek is able to reveal when a supposed “random” outlier is actually part of a **novel but coherent group** of data. You might discover, for instance, a cluster of images that all contain a new company logo that wasn’t in your training set (hence your model missed them as unsafe content), or a cluster of insurance claim photos showing a type of damage that was previously unseen. Mixpeek doesn’t just flag these items individually – it *groups them, tags them, and flags the cluster* for you. In other words, it treats the “unknown class” as its own entity to be understood, rather than noise. It’s outlier detection reimagined: the system brings the out-of-distribution group to your attention, often assigning it provisional labels or metadata (e.g. “Cluster 7: unusual motion event”).

Now, armed with this knowledge, you can close the loop and improve your training dataset. Once an **anomaly cluster** is identified in Mixpeek, you can take representative feature vectors from that cluster and use them to **search your entire dataset for similar items**. This step is crucial – it finds other data points that are similar to the anomalies but perhaps weren’t obvious outliers on their own. Mixpeek’s vector search will surface all content in Tigris that bears resemblance to the cluster’s centroid or example points. Very quickly, you’ve gone from one or two weird examples to a whole *collection of related out-of-distribution samples*. For instance, from one video showing a new kind of unsafe behavior, Mixpeek might find 20 more short clips with the same pattern hidden in your archives.

At this stage, you can loop in human annotators or domain experts. Mixpeek supports an efficient **human-in-the-loop workflow** for this: it can pre-tag the cluster of anomalies with an interim label and then you pass them to an annotation interface where humans confirm or refine those labels. Because all the similar anomalies were surfaced together, the annotators can rapidly validate them as a new class or flag if some are not relevant. This targeted annotation is much faster than random sampling. After annotation, you now have a set of previously unlabeled outliers turned into a **new labeled subset** of your dataset. You can feed this back into model training (perhaps fine-tuning your classifier on these new examples) to teach the model about this “unknown” class. In our example, the model would learn the new unsafe behavior or the new logo, and thus perform better in future.

This use case demonstrates a powerful virtuous cycle enabled by Mixpeek and Tigris: *discover -> label -> enrich dataset -> retrain -> improve model*. The ability to find anomalies and their similar counterparts in an automated way is something that would be exceedingly difficult with a manual pipeline. Mixpeek’s own description encapsulates it well: *“Don’t discard the weird. Extract it. Cluster it. Understand it.”* With Tigris as the data source, this process scales to millions of files and terabytes of data. Yet the result is actionable insight that is **immediately translated into better training data**.

## Comparing to a Traditional Stack

It’s worth highlighting just how much friction is removed by the Mixpeek + Tigris approach compared to a traditional DIY data stack:

* **Storage & Distribution:** Traditionally, you might use Amazon S3 for storage and add a CDN (like CloudFront) on top for global access. That adds configuration complexity and eventual consistency issues. With Tigris, global distribution is built-in – *no separate CDN needed* – and it offers strong consistency and active-active replication by default. You also avoid S3’s egress costs when moving data for processing, which can save a lot in a heavy pipeline.

* **Data Ingestion:** In a DIY setup, you would need to write glue code or set up S3 event triggers (perhaps AWS Lambda) to detect new files and kick off processing. Mixpeek handles ingestion automatically once connected to Tigris. It continuously watches the bucket and indexes new or updated content without you building a separate ingestion pipeline.

* **Feature Extraction:** Without Mixpeek, you’d be maintaining a patchwork of scripts or microservices for different media types – e.g., a Python script to run OpenCV or a pre-trained CNN on images, another service to call an ASR (speech-to-text) API for audio, etc. Each would produce outputs that you’d have to collect and store. Mixpeek gives a unified framework where all these extraction tasks are configured declaratively and executed in a coordinated way. It manages the scaling (spinning up workers, possibly using systems like Ray or SageMaker behind the scenes) and the fail-safe details (retries, caching, etc.), so you don’t have to reinvent that infrastructure.

* **Indexing & Search:** A manual approach would require setting up a database or specialized engine to index the extracted features. For text, maybe an Elasticsearch; for vectors, maybe a self-hosted FAISS or a cloud vector DB. You’d then have to build a custom API to query these. Mixpeek bundles this all transparently – it uses a specialized vector store under the hood (Qdrant in their current architecture) and provides simple APIs/SDK for querying. Developers can use natural language queries or filters without knowing the details of vector math or database queries. Moreover, Mixpeek’s **hybrid search** (combining text and vectors with metadata) and support for things like multi-vector queries (ColBERT late interaction) are advanced features that would be non-trivial to implement from scratch.

* **Clustering & Analysis:** In the DIY scenario, after extraction you might dump embeddings and then run a separate clustering job (using, say, Python sklearn or custom code) to group data. Doing that at scale (millions of points) is challenging and would likely require downsampling or big compute. Mixpeek provides clustering as a built-in operation – leveraging the indexed vectors and performing batch searches to group items efficiently. It’s optimized to handle large scales with the underlying vector engine. The output of clustering is directly integrated into the Mixpeek UI or API, so you can immediately act on clusters (e.g., retrieve items in a cluster, assign a label, etc.) without exporting data to another environment.

* **Labeling Workflow:** Without an integrated tool, you might export a list of file paths to a labeling tool, then later merge the labels back. This is not only slow but can introduce errors (losing track of versions, etc.). Mixpeek’s approach keeps the annotators and the data in the same loop – using AI to assist them and tracking all changes. The taxonomy feature ensures labeling is consistent and you’re not managing separate label maps in spreadsheets, for example.

* **End-to-End Traceability:** A traditional pipeline composed of multiple services often lacks a single source of truth for how a particular dataset was created. Mixpeek, acting as a multimodal warehouse, version-controls each stage (raw data, extracted features, cluster assignments, annotations). If you need to reproduce a dataset or explain to regulators what data a model was trained on, you can retrieve that lineage easily. In a DIY stack, you might have to dig through S3 logs, ETL pipeline logs, and multiple databases to piece that together – if it’s even recorded.

In summary, **the legacy approach** to dataset preparation required a lot of custom engineering and glued-together components (object storage, ETL jobs, vector DB, search interfaces, etc.). **The Mixpeek + Tigris approach** provides a *unified, automated pipeline* that handles these concerns out-of-the-box. Developers and data engineers can focus on higher-level tasks – like defining what features matter for their domain, or interpreting the clusters and search results – rather than plumbing. This not only saves development time, but it also leads to more *robust and consistent datasets*. By automating feature engineering and surfacing edge cases, the combined solution helps ensure your training data is both comprehensive and of high quality.
